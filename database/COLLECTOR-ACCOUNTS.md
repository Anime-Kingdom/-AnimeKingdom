## Account implementation

- `customer-account.html`, `.css`, `.js`: responsive collector passport and verified email authentication using the locally hosted official Supabase JavaScript SDK 2.58.0 (MIT).
- `customer-profiles.sql`: applied to the existing Supabase project. Profiles use the authenticated user's UUID; the public-facing ID is generated by the database starting at AK–10001. Customer input cannot choose another user, email or collector ID.
- Profiles contain required name and Indian mobile number, plus optional favourite character and delivery details. These are personal data, distinct from the public product catalog.
- Anonymous reads and saves are denied. Authenticated users can read their own row; the existing `ak_is_admin()` administrator can read profiles. Direct customer inserts/updates/deletes are denied. A validated RPC saves a profile only for a confirmed email account.
- `account-admin.js` is loaded from `public/admin/index.html` and reuses existing administrator authentication. The public storefront never fetches customer profiles.
- Supabase's existing administrator site URL is preserved. Only the exact customer callback `https://animekingdom.in/customer-account.html` was added to the redirect allowlist.

## Remaining activation step — free email delivery

No paid service or subscription was enabled. The project's default Supabase sender is still configured; public email sign-in has therefore **not** been activated. The customer page honestly shows “Collector accounts are opening soon,” and guest shopping remains available.

To activate without selecting a paid plan:

1. The owner must sign into/create a free email sender account, such as Resend's free plan, and verify an owned sender domain using the provider's dashboard. Account acceptance and new SMTP credentials must be handled by the owner directly.
2. Enter that provider's SMTP details directly in Supabase Authentication → Emails → SMTP Settings. Never commit the SMTP password or paste it into chat. Follow the provider's current free usage limits; do not enable paid upgrades or paid overages.
3. Send and verify a real sign-in email to a non-team customer test address, on the same browser, confirming the exact callback.
4. Set `emailDeliveryReady=true` in `customer-account.js`, publish it, increment the script query version in the account HTML and clear the hosting cache.
5. Verify profile creation/editing, persistent identity, logout, two-user isolation and administrator viewing with real authorized test accounts before announcing accounts as available.
